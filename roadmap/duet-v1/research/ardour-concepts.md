# Ardour architecture map for a Rust rewrite of the concepts

All paths are absolute. No code is copied. Only designs, names, invariants and rules follow.

## 1. Time model (`libs/temporal`)

- **`timepos_t` — one 62-bit position with a domain flag.** `/Users/james/Developer/ardour/libs/temporal/temporal/timeline.h`. A position is always measured from timeline zero and is always non-negative; one flag bit selects the unit, so the value counts either superclocks (audio domain) or musical ticks (beat domain), and the same type serves both a note and a waveform.
- **`timecnt_t` — a distance plus the position where it starts.** `/Users/james/Developer/ardour/libs/temporal/temporal/timeline.h`. A duration is not a scalar: "3 beats" has no length in samples until you know where it starts, so every count keeps its own origin `timepos_t`, and `distance()` and `position()` can be in different domains.
- **No `operator-` on positions.** `/Users/james/Developer/ardour/libs/temporal/temporal/timeline.h`. Ardour removed subtraction from `timepos_t` on purpose, because "move back" gives a position and "how far apart" gives a duration; the API forces `earlier()`, `shift_earlier()` and `distance()` instead, which removes a whole class of unit errors.
- **`superclock_t` — the audio-domain unit.** `/Users/james/Developer/ardour/libs/temporal/temporal/superclock.h`. Audio time is stored in superclocks, not samples, so that a sample-rate change does not move existing material; `superclock_to_samples()` and `samples_to_superclock()` convert with integer `muldiv` and a rounded direction, never with floats.
- **`Beats` — integer ticks at 1920 PPQN.** `/Users/james/Developer/ardour/libs/temporal/temporal/beats.h` and `/Users/james/Developer/ardour/libs/temporal/temporal/types.h`. Musical time is an `int64_t` tick count; 1920 has many integer factors, so triplets, quintuplets and common divisions stay exact.
- **`BBT_Time` — bars, beats and ticks, with bars and beats one-based.** `/Users/james/Developer/ardour/libs/temporal/temporal/bbt_time.h`. Bar 0 or beat 0 throws; the default is `1|1|0`; BBT is not monotonic across the map (a bar marker can reset it), while `Beats` is always monotonic.
- **`TempoMap` — a sorted list of `TempoPoint`, `MeterPoint` and `MusicTimePoint`.** `/Users/james/Developer/ardour/libs/temporal/temporal/tempo.h`. Each `Point` holds superclock, beats and BBT for itself, all three kept in sync, because a `Point` may not call back into the map to convert; this breaks the circular dependency at the base of the design.
- **Domain conversion is a map query, and it is the "expensive" path.** `/Users/james/Developer/ardour/libs/temporal/temporal/tempo.h`. `TempoMap::superclock_at(Beats)`, `quarters_at(timepos_t)`, `bbt_at()` and `convert_duration()` do the work; `timepos_t` compares two values in one instruction when the domains match, and falls back to a map call only when they differ.
- **The map is read through RCU plus a thread-local pointer.** `/Users/james/Developer/ardour/libs/temporal/temporal/tempo.h`. A thread calls `TempoMap::fetch()` once per cycle and then `use()` everywhere; a writer calls `write_copy()`, edits, then `update()`. A real-time thread therefore never takes a lock and never sees a half-edited map, and a long multi-step edit stays consistent.
- **`TimeDomainProvider` — domain inheritance down a tree.** `/Users/james/Developer/ardour/libs/temporal/temporal/domain_provider.h`. An object either owns a domain or inherits the parent's domain (session → track → playlist → region → automation list), and a change sends a signal down the tree.
- **`DomainBounceInfo` — a recorded, reversible domain swap.** `/Users/james/Developer/ardour/libs/temporal/temporal/domain_swap.h`. When an object moves from beats to samples, the old values are saved in a map so that undo can restore them exactly.
- **`ScopedTempoMapOwner` — a local map for a local view.** `/Users/james/Developer/ardour/libs/temporal/temporal/scope.h`. An editor window can install its own map with RAII scope guards, so a clip editor with its own tempo does not disturb the global timeline.

## 2. Session object graph and the processor chain

- **`Session` owns routes, playlists, sources, locations and the butler.** `/Users/james/Developer/ardour/libs/ardour/ardour/session.h`. The route list is held in a `SerializedRCUManager`, so `get_routes()` gives a snapshot that stays valid while another thread adds a track.
- **`Route` is a linear `std::list<std::shared_ptr<Processor>>` plus an input `IO` and an output `IO`.** `/Users/james/Developer/ardour/libs/ardour/ardour/route.h`. Channel counts must agree along the whole list; `configure_processors()` runs a negotiation pass and rejects an insert that cannot match.
- **`Track : Route` adds a playlist and record arm.** `/Users/james/Developer/ardour/libs/ardour/ardour/track.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/audio_track.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/midi_track.h`. A bus is a route with no disk; a track is a route with a `DiskReader`, a `DiskWriter` and one playlist per data type.
- **`Processor` is the one abstract element.** `/Users/james/Developer/ardour/libs/ardour/ardour/processor.h`. Every strip element — plugin, send, meter, fader, disk reader — answers `can_support_io_configuration()`, `configure_io()` and `run()`, so the chain has exactly one node type.
- **`PluginInsert` wraps one or more plugin instances with a pin map.** `/Users/james/Developer/ardour/libs/ardour/ardour/plugin_insert.h`. It can replicate a mono plugin across channels, and it holds sidechain ports in its own `IO`.
- **`IO` is a named set of ports of mixed type; `Port` is one endpoint with a latency range.** `/Users/james/Developer/ardour/libs/ardour/ardour/io.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/port.h`. One `IO` can hold audio ports and MIDI ports together.
- **`Delivery` is the single write-to-ports element, and `Role` tells you which kind.** `/Users/james/Developer/ardour/libs/ardour/ardour/delivery.h`. `Main`, `Send`, `Insert`, `Listen`, `Aux`, `Foldback`. `Send : Delivery` and `InternalSend : Send`; `Return : IOProcessor` and `InternalReturn` collects data from every internal send that targets this route.
- **`Amp` is one gain stage; the fader and the trim are two instances of it.** `/Users/james/Developer/ardour/libs/ardour/ardour/amp.h`. There is no separate "fader" class.
- **`PeakMeter` is a processor that you move.** `/Users/james/Developer/ardour/libs/ardour/ardour/meter.h`, `MeterPoint` enum in `/Users/james/Developer/ardour/libs/ardour/ardour/types.h`. The meter position is `MeterInput`, `MeterPreFader`, `MeterPostFader`, `MeterOutput` or `MeterCustom`, and the meter is re-inserted in the list when the point changes.
- **`PannerShell` holds the `Panner` inside the main `Delivery`.** `/Users/james/Developer/ardour/libs/ardour/ardour/panner_shell.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/panner.h`. The shell picks a panner implementation from the in/out channel counts, so the route does not know the panner type.
- **Invisible processors are rebuilt, never edited by the user.** `Route::setup_invisible_processors` in `/Users/james/Developer/ardour/libs/ardour/route.cc`. The user list holds only visible items; every cycle-critical element is inserted at a fixed place by rule.

**Chain order on an audio track, input to main out** (as built by `setup_invisible_processors`):

```
input IO ports
  -> InternalReturn        (aux sends from other routes arrive here)
  -> DiskWriter            (writer always precedes reader; asserted)
  -> DiskReader
  -> PolarityProcessor     (phase invert, just after the reader)
  -> TriggerBox
  -> Trim (Amp)
  -> user pre-fader processors: plugins, sends, inserts
  -> PeakMeter             (only if meter point == MeterPreFader)
  -> Amp ("Fader")
  -> monitor send / foldback sends
  -> user post-fader processors
  -> PeakMeter             (if meter point == MeterPostFader)
  -> Delivery "main outs"  (contains PannerShell)
  -> PeakMeter             (if meter point == MeterOutput)
  -> output IO ports
```

`DiskIOPoint` (`/Users/james/Developer/ardour/libs/ardour/ardour/types.h`) moves the reader and writer pair: `DiskIOPreFader` (before trim), `DiskIOPostFader` (just before main outs), or `DiskIOCustom` (the user places them, and they become visible).

## 3. Non-destructive edit model

- **`Source` is the immutable media; `Region` is a view of it.** `/Users/james/Developer/ardour/libs/ardour/ardour/source.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/region.h`. A source has flags `Writable`, `Removable`, `RemovableIfEmpty` and a `natural_position`; an edit never touches source bytes.
- **The region invariant is three numbers.** `/Users/james/Developer/ardour/libs/ardour/ardour/region.h`: POSITION is the first sample on the timeline, START is the first sample inside the source, LENGTH is the sample count. Position lives inside `_length.position()`, so a region cannot hold a position and a length in mismatched domains.
- **Trim and split only change those three numbers.** `Region::trim_front`, `trim_end`, `trim_to` in `/Users/james/Developer/ardour/libs/ardour/ardour/region.h`; `Playlist::split_region`, `Playlist::split`, `Playlist::partition`, `Playlist::cut`, `Playlist::copy`, `Playlist::paste` in `/Users/james/Developer/ardour/libs/ardour/ardour/playlist.h`. A split makes two regions over the same source, marked `_left_of_split` and `_right_of_split`.
- **`Playlist` is an ordered, layered region list with a freeze/thaw batch mode.** `/Users/james/Developer/ardour/libs/ardour/ardour/playlist.h`. `freeze()` suppresses signals, the edit runs, `thaw()` emits one change; `ThawList` guarantees that every touched region is released.
- **Layer decides audibility, and `opaque` decides whether a lower layer shows through.** `Region::layer()`, `Region::opaque()` in `/Users/james/Developer/ardour/libs/ardour/ardour/region.h`; `Playlist::top_region_at()`, `Playlist::audible_regions_at()`, `Playlist::set_layer()` in `/Users/james/Developer/ardour/libs/ardour/ardour/playlist.h`. A transparent region sums with what is under it; an opaque region hides it.
- **One track can own many playlists, and a playlist can be shared.** `/Users/james/Developer/ardour/libs/ardour/ardour/session_playlists.h` (`playlists_for_track()`, `get_unused()`), `Playlist::shared()` and `_shared_with_ids` in `/Users/james/Developer/ardour/libs/ardour/ardour/playlist.h`. "Takes" is a set of playlists on one track; a take swap is a pointer swap through `DiskIOProcessor::use_playlist()` in `/Users/james/Developer/ardour/libs/ardour/ardour/disk_io.h`.
- **A take becomes regions through `CaptureInfo`.** `Track::use_captured_audio_sources` in `/Users/james/Developer/ardour/libs/ardour/track.cc`, `CaptureInfo` in `/Users/james/Developer/ardour/libs/ardour/ardour/types.h`. The writer produces one whole-file region that covers the new source, then one region per capture pass (`start`, `samples`, `loop_offset`, `xruns`); each new region is added and then pushed to the top layer, and the whole batch is one `StatefulDiffCommand` on the playlist.
- **Crossfades are per-region fade curves, not separate objects.** `/Users/james/Developer/ardour/libs/ardour/ardour/audioregion.h`. Each audio region holds `fade_in`, `fade_out`, `inverse_fade_in`, `inverse_fade_out` and `envelope`, all as `AutomationList` curves, plus a scalar `scale_amplitude`. The inverse fades give the crossfade against the layer below. `FadeShape` is in `/Users/james/Developer/ardour/libs/ardour/ardour/types.h`.
- **Region groups replace implicit "equivalent region" rules.** `Region::RegionGroupRetainer` in `/Users/james/Developer/ardour/libs/ardour/ardour/region.h`. An import, a record pass or a paste assigns one group id under RAII, so every region made by one operation selects as a unit.
- **`Location` is the only marker type.** `/Users/james/Developer/ardour/libs/ardour/ardour/location.h`. One class with a flag set covers marks, ranges, loop, punch, session range, skip, cue, section, scene and xrun marks; a mark is a range with equal start and end.

## 4. Record modes, punch, loop, disk and latency

- **`RecordMode` has three values with three different playlist effects.** `/Users/james/Developer/ardour/libs/ardour/ardour/types.h` and `Track::use_captured_audio_sources` in `/Users/james/Developer/ardour/libs/ardour/track.cc`. `RecLayered` adds the new region on top and keeps the old one under it; `RecNonLayered` auto-partitions, so the new region cuts a hole; `RecSoundOnSound` marks the new region transparent, so both sound together.
- **`RecordState` is a three-step state machine.** `/Users/james/Developer/ardour/libs/ardour/ardour/types.h`: `Disabled`, `Enabled` (armed), `Recording` (transport rolls and punch allows it). `Session::maybe_enable_record()`, `disable_record()`, `step_back_from_record()` in `/Users/james/Developer/ardour/libs/ardour/ardour/session.h`.
- **Punch and loop are `Location` flags, and they are mutually exclusive at run time.** `IsAutoPunch` and `IsAutoLoop` in `/Users/james/Developer/ardour/libs/ardour/ardour/location.h`; `_punch_or_loop` and `maybe_allow_only_punch()` in `/Users/james/Developer/ardour/libs/ardour/ardour/session.h`. The session holds an atomic lock that refuses to arm both.
- **Loop record yields one `CaptureInfo` per loop pass.** `DiskWriter::transport_looped()`, `_num_captured_loops` in `/Users/james/Developer/ardour/libs/ardour/ardour/disk_writer.h`. Each pass keeps a `loop_offset`, so the regions align to the loop start and not to the wall time.
- **`DiskWriter` and `DiskReader` are processors around ring buffers.** `/Users/james/Developer/ardour/libs/ardour/ardour/disk_writer.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/disk_reader.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/disk_io.h`. Each channel has a `PBD::PlaybackBuffer` to read and a `PBD::RingBufferNPT` to write; the real-time thread only moves samples in and out of those buffers, and `buffer_load()` reports the margin.
- **Pre-roll and count-in are sample budgets, not states.** `Session::preroll_samples()`, `_remaining_latency_preroll`, `_count_in_samples`, `_count_in_once`, `request_preroll_record_trim()` in `/Users/james/Developer/ardour/libs/ardour/ardour/session.h`. Latency pre-roll runs the graph before the reported transport moves; the extra samples are trimmed off the front of the new region by `preroll_off`.
- **`LatencyRange` is a min/max pair per port, in two directions.** `/Users/james/Developer/ardour/libs/ardour/ardour/types.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/port.h`. A port carries a *private* range (what this route contributes) and a *public* range (what the outside world should believe), so the graph can be solved without a cycle.
- **`Route::update_signal_latency()` walks the chain and programs the delay lines.** `/Users/james/Developer/ardour/libs/ardour/ardour/route.h`, body in `/Users/james/Developer/ardour/libs/ardour/route.cc`. It sums processor latency, then compensates sends first so that `Send::effective_latency()` is correct, and it aligns a route with unconnected output to the master bus.
- **`Latent` lets the user override a plugin's reported latency.** `/Users/james/Developer/ardour/libs/ardour/ardour/latent.h`. `effective_latency()` returns zero when a global switch forces zero, else the user value, else the measured value; a plugin that lies is correctable without a code change.
- **Capture alignment is a per-track policy.** `AlignStyle` / `AlignChoice` in `/Users/james/Developer/ardour/libs/ardour/ardour/types.h`, `Track::set_align_choice()` in `/Users/james/Developer/ardour/libs/ardour/ardour/track.h`. `CaptureTime` puts the take where the clock said; `ExistingMaterial` shifts it back by the input latency so that it lines up with what the player heard.

## 5. Process cycle, threads and the backend abstraction

- **`AudioBackend` drives everything; the session is a callback.** `/Users/james/Developer/ardour/libs/ardour/ardour/audio_backend.h`. The backend owns the thread and calls `AudioEngine::process_callback(nframes)`; nothing else pulls.
- **`Session::process(nframes)` runs on the backend thread.** `/Users/james/Developer/ardour/libs/ardour/session_process.cc`. First it refreshes the thread-local tempo map, then it checks whether butler work has finished, then it fetches buffers, then it runs the IO-plugin chain and the route graph. It never allocates and never blocks.
- **`Graph` is a work-stealing DAG executor with a trigger queue.** `/Users/james/Developer/ardour/libs/ardour/ardour/graph.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/graphnode.h`. Each `GraphNode` (a route) holds an atomic ref count of upstream feeds; when the count reaches zero the node is pushed on a lock-free `MPMCQueue` and any idle worker takes it. A cycle ends when every terminal node is done.
- **`GraphChain` is an immutable, pre-computed topology.** `/Users/james/Developer/ardour/libs/ardour/ardour/graph.h`. The node list, the initial trigger list and the terminal count are built off the real-time thread and then handed over as a `shared_ptr`, so a connection change never edits a live graph.
- **`PBD::RCU` is the general rule for "real-time reads, slow writes".** `/Users/james/Developer/ardour/libs/pbd/pbd/rcu.h`. `reader()` needs no lock; `write_copy()` and `update()` are serialized by a mutex and may be as slow as they like; an old reader keeps its copy alive until it drops the pointer.
- **`PBD::RingBuffer` and friends are the only cross-thread data path.** `/Users/james/Developer/ardour/libs/pbd/pbd/ringbuffer.h`, `playback_buffer.h`, `mpmc_queue.h`. Size is rounded up to a power of two and masked, so no modulo and no branch in the hot loop; `get_read_vector()` returns at most two contiguous spans, which lets the caller `memcpy` across the wrap.
- **`Butler` is the single disk thread.** `/Users/james/Developer/ardour/libs/ardour/ardour/butler.h`. It refills every playback buffer, flushes every capture buffer, runs delegated work from an MPMC queue, and deletes dead per-thread pools; the real-time thread only sets a flag ("need butler") and never waits.
- **Real-time allocation goes through pools, never `malloc`.** `/Users/james/Developer/ardour/libs/pbd/pbd/pool.h`, `/Users/james/Developer/ardour/libs/ardour/ardour/session_event.h`. A `SessionEvent` comes from a per-thread `CrossThreadPool`: one thread allocates, one other thread frees, and the pool is returned to the butler for deletion when the thread exits.
- **`PortEngine` is the port half of the backend contract.** `/Users/james/Developer/ardour/libs/ardour/ardour/port_engine.h`. Its header states the latency definitions the whole program relies on: *capture latency* is the age of data read from a port; *playback latency* is the delay until data written will reach a terminal port.

## 6. Plugin abstraction and GUI embedding

- **`Plugin` is a pure interface over parameters and state.** `/Users/james/Developer/ardour/libs/ardour/ardour/plugin.h`. `unique_id()`, `parameter_count()`, `get_parameter()`, `automatable()`, `has_editor()`, `plugin_latency()`, `tailtime()`; the host never learns the format.
- **`PluginInfo` is a discovery record, separate from an instance.** `/Users/james/Developer/ardour/libs/ardour/ardour/plugin.h` and `/Users/james/Developer/ardour/libs/ardour/ardour/plugin_scan_result.h`. Scan results are cached on disk per format, so start-up does not re-scan.
- **`PluginManager` isolates a scan in a child process.** `/Users/james/Developer/ardour/libs/ardour/ardour/plugin_manager.h`. `auv2_scanner_bin_path`, `vst2_scanner_bin_path` and `vst3_scanner_bin_path` name separate executables (`/Users/james/Developer/ardour/libs/fst/vst2-scanner.cc`, `vst3-scanner.cc`), and there is a blacklist, a cache version, a scan timeout and a per-plugin scan log. A plugin that crashes on load cannot take the host down and is remembered as bad.
- **`PluginInsert` is the only place a plugin meets the audio graph.** `/Users/james/Developer/ardour/libs/ardour/ardour/plugin_insert.h`. It owns the pin map, the sidechain `IO` and the replication count.
- **Concrete formats.** LV2 `/Users/james/Developer/ardour/libs/ardour/ardour/lv2_plugin.h`; VST3 `/Users/james/Developer/ardour/libs/ardour/ardour/vst3_plugin.h`; Audio Unit `/Users/james/Developer/ardour/libs/ardour/ardour/audio_unit.h`; VST2 through `/Users/james/Developer/ardour/libs/ardour/ardour/linux_vst_support.h` and `mac_vst_support.h` over `/Users/james/Developer/ardour/libs/fst/fst.h`; Lua `/Users/james/Developer/ardour/libs/ardour/ardour/luaproc.h`. The bundled Steinberg headers are at `/Users/james/Developer/ardour/libs/vst3/`.
- **The host passes a native parent handle, and the plugin creates its view inside it.** The type of handle is per platform:
  - **macOS / VST3:** the host makes an `NSView`, calls the VST3 `IPlugView::attached(handle, kPlatformTypeNSView)`, and then re-parents that view into the GTK window's Quartz `NSView`. `/Users/james/Developer/ardour/gtk2_ardour/vst3_nsview_plugin_ui.mm`.
  - **X11 / VST3:** the host passes an X11 embed window id with `kPlatformTypeX11EmbedWindowID`, inside a GTK `Socket`. `/Users/james/Developer/ardour/gtk2_ardour/vst3_x11_plugin_ui.cc`.
  - **Windows / VST3:** `kPlatformTypeHWND`. `/Users/james/Developer/ardour/gtk2_ardour/vst3_hwnd_plugin_ui.cc`.
  - **Audio Unit:** the host reads `kAudioUnitProperty_CocoaUI`, loads the named factory class from the plugin's bundle, asks the factory for a view, and adds that `NSView` as a subview. `/Users/james/Developer/ardour/gtk2_ardour/au_pluginui.mm`.
  - **VST2 on Linux:** the plugin returns an X11 window id (`xid`), which is re-parented into a GTK `Socket`. `/Users/james/Developer/ardour/gtk2_ardour/lxvst_plugin_ui.cc`. On macOS it is again an `NSView`: `/Users/james/Developer/ardour/gtk2_ardour/mac_vst_plugin_ui.mm`.
- **Resize is a two-way negotiation.** `VST3PI : IPlugFrame` with `resizeView()` in `/Users/james/Developer/ardour/libs/ardour/ardour/vst3_plugin.h`, and `forward_resize_view()`. The plugin asks the host for a size and the host answers; the host must not just force a size.
- **Every format also has a generic fallback UI.** `/Users/james/Developer/ardour/gtk2_ardour/plugin_ui.h`. `Plugin::has_editor()` returns false, or the user asks for it, and the host draws controls from the parameter descriptors alone.

## 7. MIDI

- **`Evoral::Event<Time>` is a time-stamped byte buffer with optional ownership.** `/Users/james/Developer/ardour/libs/evoral/evoral/Event.h`. When it does not own the buffer, every method is real-time safe; a deep copy is opt-in.
- **`Evoral::Note<Time>` is an on/off pair, not two events.** `/Users/james/Developer/ardour/libs/evoral/evoral/Note.h`. `set_time()` moves the off event too and `set_length()` recomputes it, so a note can never be left unterminated.
- **`Evoral::Sequence<Time>` keeps notes and controllers in one object with a reader/writer lock.** `/Users/james/Developer/ardour/libs/evoral/evoral/Sequence.h`. Notes are a multiset ordered by start time; the read iterator carries a priority queue of active notes ordered by end time, so a read of any window emits the correct note-offs. Stuck notes have a declared policy (`DeleteStuckNotes` or `ResolveStuckNotes`).
- **`Evoral::ControlList` is the one curve type, for MIDI CC and for plugin automation alike.** `/Users/james/Developer/ardour/libs/evoral/evoral/ControlList.h`. It is a `TimeDomainProvider` and a `TimeDomainSwapper`, so an automation curve can be locked to beats or to samples; `thin()`, `eval()` and a lookup cache serve the drawing and the audio path.

## 8. State and undo

- **Session file layout.** `/Users/james/Developer/ardour/libs/ardour/ardour/session_directory.h` and `/Users/james/Developer/ardour/libs/ardour/ardour/directory_names.h`:
  - `<session>/<snapshot>.ardour` — the XML state (`statefile_suffix`); `.ardour.bak` is the backup; `.pending` holds unsaved capture state after a crash.

- **`Session::save_state()` is atomic and typed.** `/Users/james/Developer/ardour/libs/ardour/ardour/session.h`. Arguments cover the snapshot name, pending state, a switch-to-snapshot flag and a template save; `snapshot_t` distinguishes a normal save, a snapshot that keeps the media, and a snapshot that copies it. Cleanup (`cleanup_sources()`) moves unreferenced media to `dead/` instead of deletion.

## Concepts to adopt

1. **`timepos_t` / `timecnt_t` with a domain flag in the value** — `/Users/james/Developer/ardour/libs/temporal/temporal/timeline.h`. One timeline type that carries its own unit is the single change that makes a shared notation-and-audio timeline possible; in Rust this is a newtype over `i64` with the tag bit, or an enum if you accept 16 bytes.
2. **No `operator-` on a position; `distance()`, `earlier()`, `shift_earlier()` instead** — same file. Rust's type system can make this an error at compile time rather than a convention, which is strictly better than what Ardour can express.
3. **`TempoMap` behind RCU plus a per-thread snapshot** — `/Users/james/Developer/ardour/libs/temporal/temporal/tempo.h`. Read is free and lock-free, write is copy-and-swap; `arc-swap` gives the same shape in Rust with far less code. **Correction, 2026-09-21 (specification revision 21, critic C19-W22): `arc-swap` is REJECTED.** An `arc-swap` reader can hold the last reference to a retired value and run its destructor inside the audio callback, which TH1 forbids. `triple_buffer` carries every core-to-audio publication instead, because a `triple_buffer` reader borrows and never owns, so the writer thread drops every retired value (ADR 0004, `architecture.md` section 5.8). `arc-swap` is a dependency of no Duet crate.
4. **Integer musical time at 1920 ticks per beat** — `/Users/james/Developer/ardour/libs/temporal/temporal/types.h`. Exact tuplets, exact round-trips, no float drift.
5. **Source / Region / Playlist with POSITION, START, LENGTH** — `/Users/james/Developer/ardour/libs/ardour/ardour/region.h`. Every edit is a number change over immutable media; this is the whole of non-destructive edit, and it is small.
6. **`RecordMode` as three playlist policies (layer / partition / transparent)** — `/Users/james/Developer/ardour/libs/ardour/track.cc`. Three lines of rule cover comping, replacement and doubling; a vocal app needs all three.
7. **One playlist per take, swapped by pointer** — `/Users/james/Developer/ardour/libs/ardour/ardour/session_playlists.h`. Take management becomes free, and it costs no media.
8. **`AudioBackend` / `PortEngine` as a trait with a dummy implementation** — `/Users/james/Developer/ardour/libs/ardour/ardour/audio_backend.h`, `/Users/james/Developer/ardour/libs/backends/dummy/`. The dummy backend is what makes headless tools and deterministic tests possible; build it first, not last.
9. **`BasicUI` — a flat, device-free verb list** — `/Users/james/Developer/ardour/libs/ctrl-interface/control_protocol/control_protocol/basic_ui.h`. This is the exact shape an AI agent needs: name a verb, pass a value. Make it the app's primary API and let the GUI be one more caller.
10. **Headless host plus a terminal REPL over the same core** — `/Users/james/Developer/ardour/headless/load_session.cc`, `/Users/james/Developer/ardour/luasession/luasession.cc`. If the core runs with no GUI on day one, the GUI cannot become the owner of state later.
11. **`Processor` as the one chain element, with `configure_io` negotiation** — `/Users/james/Developer/ardour/libs/ardour/ardour/processor.h`. One trait, one `run`, and a channel-count contract that rejects a bad insert before audio flows.
12. **Waveform: min/max peak file plus a global image cache plus worker threads with cancellable requests** — `/Users/james/Developer/ardour/libs/waveview/waveview/wave_view_private.h`. Draw a placeholder, never block the UI thread, abandon obsolete work. **Correction, 2026-09-21 (specification revision 21, critic C19-W22): the GLOBAL image cache is REJECTED.** ADR 0006 and `architecture.md` section 10.5 give each lane its own bounded `PathCache` keyed by `SystemId`, with B61 and B62 as the bounds, because a global cache is shared mutable state across views and a second owner of one value. The other three halves of this item, the min-max peak file, the worker threads, and the cancellable request, are adopted.
13. **`StatefulDiffCommand` + `begin/commit_reversible_command`** — `/Users/james/Developer/ardour/libs/pbd/pbd/stateful_diff_command.h`, `/Users/james/Developer/ardour/libs/pbd/pbd/history_owner.h`. Property-level diffs make undo cheap, and `abort_empty_reversible_command()` prevents empty history entries.
14. **`interchange/<session>/audiofiles` plus `peaks/` and `analysis/` beside a plain-text state file** — `/Users/james/Developer/ardour/libs/ardour/ardour/session_directory.h`. Media is findable without the app; derived data is separate and can be deleted.
15. **`RippleInterview` mode** — `/Users/james/Developer/ardour/libs/ardour/ardour/types.h`. Remove a range and close the gap on every track: the core spoken-word and vocal-comp edit.
16. **pYIN's method: per-frame candidate distribution, then an HMM over the whole take** — `/Users/james/Developer/ardour/libs/vamp-pyin/`. Do not smooth a frame-local pitch track; decode a path.
17. **Out-of-process plugin scan with a blacklist and a versioned cache** — `/Users/james/Developer/ardour/libs/ardour/ardour/plugin_manager.h`. A third-party crash must not be able to kill the app.
18. **`Location` as one flagged type for every timeline mark** — `/Users/james/Developer/ardour/libs/ardour/ardour/location.h`. One table, one renderer, one serializer.

## Concepts to reject

- **The invisible-processor rebuild** — `Route::setup_invisible_processors` in `/Users/james/Developer/ardour/libs/ardour/route.cc`. A 300-line imperative function that inserts elements by search-and-splice, guarded by asserts and by a post-hoc "make sure the writer is before the reader" fix-up. Encode the chain as a typed fixed skeleton with user slots, so the order is correct by construction.
- **`shared_ptr` everywhere as the ownership model** — throughout `/Users/james/Developer/ardour/libs/ardour/ardour/`. This forces `weak_ptr` cycles, `enable_shared_from_this`, and a whole `drop_references()` protocol. In Rust use arenas with generational ids for the object graph and reserve `Arc` for the real-time hand-off only.
- **XML as the state format** — `/Users/james/Developer/ardour/libs/pbd/pbd/xml++.h`. It is verbose, untyped and needs hand-written `set_state(node, version)` on every class. Use `serde` with an explicit schema version.
- **The C++ macro time-domain scope trick** — `ScopedTempoMapOwner` and `EC_LOCAL_TEMPO_MAP_SCOPE` in `/Users/james/Developer/ardour/libs/temporal/temporal/scope.h`. Its own comment calls the requirement "a bit ugly": every method of a derived class must begin with a macro. Pass the map, or hold it in the view struct.
- **Thread-local implicit context for conversion** — `TempoMap::use()` in `/Users/james/Developer/ardour/libs/temporal/temporal/tempo.h`. It makes `timepos_t::beats()` silently depend on hidden state, and it needs a `fetch_condition()` assert to catch misuse. Make the map an explicit argument to any conversion.
- **A single global `Session` god object** — `/Users/james/Developer/ardour/libs/ardour/ardour/session.h` is over 2300 lines of declarations. Split transport, routing, media and persistence into separate owners.
- **libsigc++ signal graphs for cross-module change notice** — `/Users/james/Developer/ardour/libs/pbd/pbd/signals.h`, used everywhere. It produces `ScopedConnection` bookkeeping, re-entrancy hazards and "EMIT SIGNAL" comments. Use explicit change events on a channel, or a reactive store.
- **Mixed GUI toolkit embedding for plugin windows** — `/Users/james/Developer/ardour/gtk2_ardour/vst3_nsview_plugin_ui.mm` and `lxvst_plugin_ui.cc`, including method swizzling on `NSView` in `/Users/james/Developer/ardour/gtk2_ardour/au_pluginui.mm`. Do not host native plugin views inside a Rust GPU-composited window in version one; ship the generic parameter UI (`Plugin::has_editor()` false path) and add native views later, per platform, behind a trait.
- **Ardour's meter-type zoo** — `MeterType` in `/Users/james/Developer/ardour/libs/ardour/ardour/types.h` has thirteen values with DIN, BBC, EBU, Nordic and three K-scales. A vocal app needs peak, RMS and LUFS. Ship three.
- **"Region group id" as a shared mutable static** — `Region::RegionGroupRetainer` with `_operation_rgroup_mutex` and `_next_group_id` in `/Users/james/Developer/ardour/libs/ardour/ardour/region.h`. Keep the group id in the command that creates the regions, not in a global counter behind a mutex.
- **`libs/staffpad` as a source of notation** — `/Users/james/Developer/ardour/libs/staffpad/README`. The name misleads: it is a time-and-pitch DSP library. Do not look here for score display; Ardour has none.
